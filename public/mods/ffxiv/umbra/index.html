A window is not a terminal

Content, launchers and presentation are independent. Dalamud modules own their data and input. Umbra extensions add toolbar buttons. The standalone Floating Windows service owns local window textures and placement. Ghostty remains a supported host for terminals and remote desktop panels.

PresentationHostWhat it provides
ScreenDalamudOrdinary movable plugin windows.
Native frameKamiToolKit adapterGame frames for Journal and Character.
Floating local windowXivHud.WindowsCompanions hover near you and trail movement on springs, then settle. View, world and ground placements; zero terminal sessions.
Terminal or remote desktopGhosttyThe existing terminal and streamed-window controls.

Use /xivwindows to choose an open source window. Return one with Screen, or recover all with /xivwindows screen. Journal and Character also retain their own screen recovery commands and an explicit Ghostty-host setting.

Local floating placement does not export the game’s UI to a phone or another computer. A separate authenticated stream transport is still needed for that direction of handoff. World projections currently draw as overlays; scene occlusion and physical controller acceptance remain separate work.

Recorded in game

Captions identify the source and whether sample data is shown. Builds, screenshots and gameplay acceptance are separate checks.

Install the family

Use the explicit development Dalamud repository and enable testing builds. Optional Umbra.XivHud.*.dll adapters are separate assets in the development release. Add those files in Umbra Settings → Plugins; after restarting Umbra, choose their widgets in the toolbar editor.

These are development builds. Native UI remains available. Source, build instructions and acceptance records describe the current limits. Inventory is read-only, crafting is planning, and previews cannot execute combat actions or send chat.
